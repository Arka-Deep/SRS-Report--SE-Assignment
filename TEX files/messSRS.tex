	% ============================================================
	
	\chapter{Abstract}
	
	Food wastage is a common problem in college and institutional messes. Food is often prepared according to estimates, but actual attendance can vary because of absences, schedule changes, or other factors. This can result in excess food and unnecessary wastage.
	
	The proposed \textbf{Mess Food Wastage Tracker and Management System} records meal attendance, food preparation, consumption, and wastage. It provides reports that help mess staff and administrators understand wastage patterns and make better decisions about future food preparation.
	
	The system follows the \textbf{Agile Software Development Model}, allowing features to be developed in small increments and improved using feedback from students, mess staff, and administrators.
	
	% ============================================================
	% 2. OBJECTIVE
	% ============================================================
	
	\chapter{Objective}
	
	The main objective is to reduce avoidable food wastage by maintaining accurate meal and food records.
	
	The system aims to:
	
	\begin{enumerate}[leftmargin=*]
		\item Record expected attendance for each meal.
		\item Maintain daily menus and meal schedules.
		\item Record prepared, consumed, and wasted food quantities.
		\item Calculate wastage and wastage percentage.
		\item Maintain historical records for comparison.
		\item Generate daily, weekly, and monthly reports.
		\item Help administrators make better food preparation decisions.
	\end{enumerate}

	\chapter{Introduction}
	
	\section{Purpose}
	
	This Software Requirements Specification defines the requirements and basic design of the Mess Food Wastage Tracker and Management System. It describes what the system should do, who will use it, and the main quality and operational requirements.
	
	\section{Scope}
	
	The system is intended for a college, hostel, or similar institutional mess. It will manage:
	
	\begin{itemize}[leftmargin=*]
		\item student meal attendance,
		\item meal schedules and menus,
		\item food preparation records,
		\item food consumption records,
		\item food wastage records, and
		\item reports and historical data.
	\end{itemize}
	
	The system focuses on food wastage tracking and management. Full accounting, procurement, or hostel-management functions are outside the present scope.

	\section{System Overview}
	
	Students can view meal information and mark their expected attendance. Mess staff record preparation, consumption, and wastage data. Administrators manage users, meals, menus, and reports. The stored data is then used to calculate wastage and identify recurring patterns.

	\chapter{SDLC Model}
	
	\section{Selected Model: Agile}
	
	The \textbf{Agile Software Development Model} is selected for this project. Agile develops software through repeated iterations rather than delivering the entire system at once.
	
	For this system, the first version can provide attendance and basic wastage recording. Features such as reports, analytics, notifications, and prediction can then be added and refined in later iterations.
	
	\section{Advantages}
	
	\begin{enumerate}[leftmargin=*]
		\item \textbf{Flexible:} Requirements can change based on user feedback.
		\item \textbf{Incremental:} Features can be developed and tested in smaller parts.
		\item \textbf{Early feedback:} Users can test features before the complete system is finished.
		\item \textbf{Early delivery:} A basic working version can be available quickly.
		\item \textbf{Easy improvement:} Problems can be identified and corrected during each iteration.
	\end{enumerate}
	
	\section{Disadvantages}
	
	\begin{enumerate}[leftmargin=*]
		\item Requires regular feedback from users.
		\item Frequent changes can make planning difficult.
		\item Poorly managed iterations may lead to insufficient documentation.
		\item Continuous feature requests can cause scope creep.
		\item Good communication between team members is necessary.
	\end{enumerate}
	
	\section{Why Agile Was Selected}
	
	The requirements of a mess-management system may become clearer only after users start using it. Students, mess staff, and administrators may have different expectations from the system.
	
	Agile allows the team to first implement the essential features and then improve the system based on actual feedback. This makes it more suitable than a rigid development process for the proposed system.
	
	A possible development sequence is:
	
	\begin{enumerate}[leftmargin=*]
		\item Requirements and planning
		\item User and meal management
		\item Attendance management
		\item Food and wastage recording
		\item Reports and analytics
		\item Testing and refinement
	\end{enumerate}

	\chapter{Overall Description}
	
	\section{Product Perspective}
	
	The proposed system is a standalone information-management system for an institutional mess. It receives information from students, mess staff, and administrators, stores it in a central database, and produces useful summaries and reports.
	
	\section{Main Functions}
	
	The main functions are:
	
	\begin{enumerate}[leftmargin=*]
		\item User authentication and role management.
		\item Meal and menu management.
		\item Student meal attendance.
		\item Food preparation and consumption recording.
		\item Food wastage recording and calculation.
		\item Historical analysis and report generation.
	\end{enumerate}
	
	\section{Users}
	
	\subsection{Student}
	
	Students can view meals and menus, mark meal attendance, and modify their attendance within the allowed time.
	
	\subsection{Mess Staff}
	
	Mess staff record prepared, consumed, and wasted quantities and can view relevant meal information.
	
	\subsection{Administrator}
	
	Administrators manage users, meals, menus, configuration, and reports.
	
	\section{Operating Environment}
	
	The system may be implemented as a web application and accessed using a modern browser on a computer or mobile device. It may use a relational database and a local or cloud-based server.
	
	\section{Constraints}
	
	The main constraints are:
	
	\begin{itemize}[leftmargin=*]
		\item The accuracy of reports depends on the accuracy of entered data.
		\item Students need access to the system to submit attendance.
		\item Network availability may be required.
		\item Mess staff may have limited time to enter data.
		\item User information must be protected from unauthorized access.
	\end{itemize}
	
	\section{Assumptions}
	
	The system assumes that users provide reasonably accurate information, mess staff record food quantities regularly, users have valid accounts, and the mess follows a defined meal schedule.

	\chapter{Requirement Specification}
	
	\section{Functional Requirements}
	
	\subsection{FR1 -- Authentication and Authorization}
	
	\begin{enumerate}[leftmargin=*]
		\item The system shall allow users to log in using valid credentials.
		\item The system shall identify the user's role after login.
		\item The system shall restrict functions according to user role.
		\item The administrator shall be able to activate or deactivate accounts.
	\end{enumerate}
	
	\subsection{FR2 -- Meal Attendance}
	
	\begin{enumerate}[leftmargin=*]
		\item The system shall display available meals for a selected day.
		\item A student shall be able to mark attendance for a meal.
		\item A student shall be able to modify attendance before the deadline.
		\item The system shall store the student, meal, and date for each attendance record.
		\item The system shall calculate expected attendance for a meal.
	\end{enumerate}
	
	\subsection{FR3 -- Menu Management}
	
	\begin{enumerate}[leftmargin=*]
		\item Authorized users shall be able to create and modify menus.
		\item A menu shall be associated with a meal.
		\item Previous menu information shall be retained as historical data.
	\end{enumerate}
	
	\subsection{FR4 -- Food Recording}
	
	\begin{enumerate}[leftmargin=*]
		\item Mess staff shall be able to record prepared food quantity.
		\item The system shall associate food records with a meal and food item.
		\item Authorized users shall be able to correct incorrect records.
	\end{enumerate}
	
	\subsection{FR5 -- Wastage Recording}
	
	\begin{enumerate}[leftmargin=*]
		\item Mess staff shall be able to record consumed and wasted quantities.
		\item The system shall calculate the remaining and wasted quantity.
		\item The system shall calculate the wastage percentage.
		\item The system shall maintain historical wastage records.
	\end{enumerate}
	
	\subsection{FR6 -- Analysis}
	
	\begin{enumerate}[leftmargin=*]
		\item The system shall calculate wastage for individual meals.
		\item The system shall provide daily, weekly, and monthly summaries.
		\item The system shall identify meals with high wastage.
		\item The system shall support comparison of wastage across dates and meals.
	\end{enumerate}
	
	\subsection{FR7 -- Reports}
	
	\begin{enumerate}[leftmargin=*]
		\item The system shall generate daily wastage reports.
		\item The system shall generate weekly and monthly reports.
		\item The system shall provide attendance and preparation summaries.
	\end{enumerate}
	
	\subsection{FR8 -- Administration}
	
	\begin{enumerate}[leftmargin=*]
		\item The administrator shall manage student and staff accounts.
		\item The administrator shall configure meal schedules.
		\item The administrator shall manage food items and menus.
		\item The administrator shall view system reports.
	\end{enumerate}
	
	% ------------------------------------------------------------
	% NON-FUNCTIONAL REQUIREMENTS
	% ------------------------------------------------------------
	
	\section{Non-Functional Requirements}
	
	\subsection{NFR1 -- Performance}
	
	\begin{enumerate}[leftmargin=*]
		\item Common operations should respond within a reasonable time.
		\item Attendance submission should require minimal processing.
		\item Reports should be generated within an acceptable time.
	\end{enumerate}
	
	\subsection{NFR2 -- Security}
	
	\begin{enumerate}[leftmargin=*]
		\item Unauthorized users shall not access protected functions.
		\item Passwords shall not be stored in plain text.
		\item Users shall only access functions allowed by their roles.
		\item Administrative operations shall require authorization.
	\end{enumerate}
	
	\subsection{NFR3 -- Usability}
	
	\begin{enumerate}[leftmargin=*]
		\item The interface should be simple and understandable.
		\item Common operations should require few steps.
		\item Error and validation messages should be clear.
	\end{enumerate}
	
	\subsection{NFR4 -- Reliability}
	
	\begin{enumerate}[leftmargin=*]
		\item Completed transactions should not result in data loss.
		\item The system should handle invalid input safely.
		\item Database backup should be supported.
	\end{enumerate}
	
	\subsection{NFR5 -- Scalability}
	
	\begin{enumerate}[leftmargin=*]
		\item The system should support increasing numbers of users and records.
		\item The architecture should allow additional mess facilities in the future.
	\end{enumerate}
	
	\subsection{NFR6 -- Maintainability}
	
	\begin{enumerate}[leftmargin=*]
		\item The system should be divided into logical modules.
		\item Major components should be documented.
		\item Changes to one module should have limited impact on others.
	\end{enumerate}
	
	\subsection{NFR7 -- Availability}
	
	The system should normally be available during mess operating hours. Planned maintenance should preferably be scheduled outside critical meal periods.

	\chapter{Conclusion and Future Work}
	
	\section{Conclusion}
	
	The Mess Food Wastage Tracker and Management System provides a structured way to record and monitor food wastage in an institutional mess. By combining attendance data with preparation and wastage records, the system can help staff understand where unnecessary waste occurs and support better meal planning.
	
	Agile is suitable for the project because the system can be developed incrementally and improved through feedback from its users.
	
	\section{Future Work}
	
	Future versions may include:
	
	\begin{enumerate}[leftmargin=*]
		\item Machine-learning based food-demand prediction.
		\item A dedicated mobile application.
		\item Automatic reminders for meal attendance.
		\item Interactive dashboards and charts.
		\item Cost estimation of wasted food.
		\item Integration with inventory and procurement systems.
		\item Support for multiple mess facilities.
		\item Integration with weighing sensors for automatic measurement.
	\end{enumerate}
